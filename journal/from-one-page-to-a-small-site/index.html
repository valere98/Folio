From one long page to a site with room to grow

A small static site can have clear, useful destinations without a framework migration.

By Valere Mbaya · 11 October 2026 · 2 min read

A portfolio often starts as one page: introduction, services, projects, contact details, all stacked in one scroll. That can be a good first version. It becomes harder to use when every new project, article, and experiment competes for another place in the same document.

In this site's existing files, there were two almost identical HTML pages and no application framework or build setup. The useful next step was not automatically a migration. It was to give important content its own address while keeping the implementation simple.

Give each task a destination

A visitor looking for a project should be able to open a project list, then share a specific project page. Someone comparing website packages should not need to scan past every project first. A journal and a small lab also deserve their own context. Clear URLs make those paths easier to understand, share, and revisit.

Plain HTML can serve these pages directly. Shared CSS and JavaScript keep the navigation, typography, responsive behavior, and small interactions consistent. The page content stays readable in the source and can be deployed as static files.

Keep the change proportional

A framework is useful when the product needs its routing, data, or rendering model. It is not a goal by itself. For a mostly informational portfolio, a small set of static pages avoids introducing dependencies and a build step before there is a concrete need for them.

The trade off is repeated page structure and more care when updating shared navigation. If the site grows into a larger publishing workflow, shared templates or a content system may become worthwhile. That decision can follow the content rather than precede it.

Start with the visitor's next question

Good structure is less about having many pages than making the next useful step obvious. The homepage can introduce the work; focused pages can then answer deeper questions about projects, services, writing, and contact. That is a modest technical change, but it gives the portfolio room to become more specific over time.

This note describes the structure implemented for this portfolio. It does not claim performance improvements or business results.
