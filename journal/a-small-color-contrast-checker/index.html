A small color contrast checker, and what it can’t tell you

A useful accessibility check should be easy to try and honest about its limits.

By Valere Mbaya · 11 October 2026 · 2 min read

Choosing a text color by eye is not always enough. A small contrast checker makes one part of that decision measurable: it compares the relative luminance of a foreground and background color, then reports their contrast ratio.

From a hex color to relative luminance

Each sRGB channel is normalized to a value from zero to one, then linearized. Values at or below 0.04045 are divided by 12.92; larger values use the transfer curve ((value + 0.055) / 1.055) raised to 2.4. The linear channels are combined with the sRGB luminance weights: 0.2126 for red, 0.7152 for green, and 0.0722 for blue.

With the lighter luminance first, the contrast ratio is (Llighter + 0.05) / (Ldarker + 0.05). The resulting ratio is at least 1:1.

const ratio =
  (lighter + 0.05) / (darker + 0.05);

const normalTextPasses = ratio >= 4.5;
const largeTextPasses = ratio >= 3;

What a passing ratio means

For WCAG AA, the commonly used minimum is 4.5:1 for normal text and 3:1 for large text. “Large” has a defined meaning in the guidance; it is not simply any text that looks a bit bigger on a screen. The checker on this site reports those two thresholds as a quick design signal.

What it does not mean

A ratio check does not assess keyboard access, focus visibility, labels, reading order, zoom behavior, motion, or whether the interface makes sense to a person using assistive technology. It also does not replace testing the actual type size, weight, and displayed colors in context.

Use the number to catch a common visual issue early, then test the complete experience. Accessibility is a quality of the product, not a single passing number.
